# Pub Compass static UK snapshot

This repository component builds a frozen pub dataset from a Geofabrik OpenStreetMap extract and publishes versioned UTF-8 data files with GitHub Pages. Requests are static-file GETs only; there are no live Overpass or other upstream queries.

## Snapshot source and coverage

The workflow downloads `https://download.geofabrik.de/europe/united-kingdom-latest.osm.pbf`. Geofabrik's United Kingdom extract includes Great Britain and Northern Ireland (and excludes the Isle of Man and Channel Islands). The current extract was about 2.1 GB when this source was checked. The workflow filters `nwr/amenity=pub`, exports geometry to GeoJSON, and keeps only each feature's name, centroid/point coordinates and raw `opening_hours`.

The snapshot is generated by running **Build and publish UK pub snapshot** from the Actions tab. It also runs monthly. Deployments use the Pages artifact actions; generated tiles and source PBF/GeoJSON files are not committed.

## Tile addressing

The UK is partitioned into one-degree root squares. The root key is:

```text
floor(latitude)_floor(longitude)
```

For example, `51_-1` covers latitude 51..52 and longitude -1..0. Each root is first divided uniformly into 1/8-degree cells using three quadtree levels. The watch derives this three-digit cell prefix from latitude/longitude and requests `index/51_-1/<prefix>.bin`. This keeps dense-city indexes small. The cell index contains only further split paths, relative to that prefix. At each split, the four children are ordered south-west `0`, south-east `1`, north-west `2`, north-east `3`. The watch follows the path for its coordinate and requests `tiles/51_-1/p<full-path>.bin`. It retains the current cell index in memory and requests another when crossing into a different 1/8-degree cell.

The builder calculates the tenth-nearest radius from each tile centre and includes every pub within that radius plus twice the maximum centre-to-corner distance. This triangle-inequality bound ensures each point in the tile has its true nearest ten among the tile's candidates. If a candidate list exceeds 40, it recursively splits the tile. A tile that still exceeds the cap at the maximum depth fails the build instead of silently returning incomplete data. Areas with no pub within about 30 km have no leaf file and return HTTP 404.

Each `.bin` file contains UTF-8 text requested as `application/octet-stream`, avoiding the MIME parameters Pages adds to text responses. The index contains `I1`, the number of split paths, then one relative path per line. A tile contains `T1`, the snapshot date, the number of pubs, then one tab-separated record per pub (`name`, latitude and longitude scaled by 10,000,000, and raw opening hours). Empty name or hours fields represent null. Tabs and line breaks in text fields are replaced with spaces so records remain unambiguous. The watch converts the returned byte array to a string before parsing.

Example tile (`<TAB>` marks a literal tab; empty name and hours fields are blank):

```text
T1
YYYY-MM-DD
2
The Red Lion<TAB>515000000<TAB>-1000000<TAB>Mo-Su 11:00-23:00
<TAB>515100000<TAB>-1100000<TAB>
```

The watch fetches the cell index and current data tile; after that, crossing a leaf boundary inside the same cell requires only the new tile GET. Confirm that GitHub Pages serves the `.bin` files as `application/octet-stream` after each format change.

## Build and verification

The workflow installs `osmium-tool` and the Python packages in `requirements.txt`, downloads the UK PBF, filters pub features, and runs:

```powershell
python server\build_tiles.py --input pubs.geojson --output site --built YYYY-MM-DD
python -m unittest discover -s server\tests
```

The builder removes same-name point/building duplicates within 30 m, writes the site attribution page, validates the nearest-ten guarantee against brute-force distance calculations for 300 deterministic random covered points, and spot-checks Ipswich, Needham Market, Glenmore in Scotland, an England tile boundary, and Belfast/Northern Ireland. It reports tile count, largest tile/index, and total site size; warns above the 500 MB target; and fails if the output exceeds GitHub Pages' 1 GB published-site limit. GitHub documents a 100 GB/month soft bandwidth limit and that rate limiting can still return HTTP 429; this project is intended for a small personal watch app, not a general-purpose data or commercial service.

## Attribution and freshness

The site displays `© OpenStreetMap contributors` and notes the Open Database License (ODbL). Keep this attribution in any redistribution of the data. A monthly rebuild refreshes the snapshot; until then, edits and closures in OSM are not reflected. Opening hours are indicative and may be incomplete or stale.

Before deploying, enable GitHub Pages with **GitHub Actions** as the publishing source in the repository settings. The watch's `PAGES_BASE_URL` must match the repository's Pages URL.
